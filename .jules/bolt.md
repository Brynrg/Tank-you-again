## 2024-06-24 - EntityMap Array Allocation Optimization

**Learning:** The game loop instances (`Arena` in shared code and `GameLoop` in server code) were caching their world state in arrays at the beginning of each bot tick logic loop. This meant calling `Array.from()` repeatedly on large maps of entities (`this.tanks.values()`, etc). In hot loops that are called 20-60 times a second, repeated map-to-array conversions trigger heavy memory allocations and result in garbage collection pauses.
**Action:** Created `EntityMap` which extends standard `Map` and adds a `valuesArray()` method. It caches the array representation of the map's values, invalidating it only upon mutation (`set`, `delete`, `clear`). Next time I see repeated map iterations in a game loop, consider if read-heavy, write-light collections should cache an array representation.
