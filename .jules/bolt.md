## 2024-05-23 - Performance Optimization: Iterator allocations in Hot Loops

**Learning:** In the `server/src/loop.ts` and `shared/sim/arena.ts`, iterating over standard iterables returned by `.values()` for map arrays like `this.tanks.values()` allocates a new iterator object each time. In a highly active game loop (executing multiple times per second for every entity like tanks, projectiles, mines, pickups), this repeatedly allocates unnecessary iterators which creates immense GC thrashing. Using `.valuesArray()` provided by the custom `EntityMap` caches these arrays and significantly cuts memory allocations. Refactoring iteration loops like `for (const t of tanks)` to `for (let i = 0; i < tanks.length; i++)` further eliminates iterable generation. Also passing `readonly Entity[]` instead of `Iterable<Entity>` for helper functions like `findHit`, `computeVisionSet`, `scanRadar`, and `stepMineDetonations` and replacing internal iterations with index-based loops eliminates array conversion overhead (`[...iterable]`).
**Action:** When working in hot paths (like tick loops), use the `EntityMap.valuesArray()` utility to fetch arrays to avoid iterator allocations, and change parameter signatures on inner-loop helper functions from `Iterable<T>` to `readonly T[]`. Always replace `for...of` array iteration with traditional index-based loops to prevent additional iterator overhead in the hottest codepaths.
